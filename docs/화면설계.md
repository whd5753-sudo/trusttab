# 5단계 화면 설계 — 리뷰 미리 검사

손님이 리뷰를 쓰면, 블록체인에 올리기 **전에** AI 문장 판정 엔진(4단계 `engine.js`)으로
점수와 판정(게시 · 보류 · 거부)을 미리 보여 주는 한 페이지 화면이다.
여러 페이지 이동(라우팅)과 지갑 연결은 6단계 이후에 한다.

## 화면 구성 (위에서 아래로)

1. **머리글** — 제목 `TrustTab` (11단계에 `FairReview` 에서 바꿈), 한 줄 설명 "결제한 손님만 쓰는 공정한 리뷰"
2. **리뷰 입력 카드**
   - 별점: 1~5 버튼 5개 (선택된 버튼 강조, 처음 값 5)
   - 리뷰 내용: 여러 줄 입력칸, 최대 300자, 아래에 `글자 수 N / 300` (N 은 `charCount` 로 계산)
   - `검사하기` 버튼 — 내용이 비어 있으면 누를 수 없음
   - 예시 버튼 3개: 기대값 표의 1번(게시) · 4번(보류) · 3번(거부) 행. 누르면 내용과 별점을 채움
3. **결과 카드** (검사하기를 누른 뒤에만 보임)
   - 점수 `N / 1000`
   - 판정 배지: 게시(초록) · 보류(주황) · 거부(빨강) — 색만이 아니라 글자로도 표시
   - 이유 목록: `reasons` 를 한 줄씩. 비어 있으면 "걸린 규칙 없음"
   - 안내 문구: "이 결과는 미리 보기입니다. 실제 게시 여부는 8단계에서 컨트랙트가 결정합니다."

## 규칙

- 점수 · 판정은 **`engine.js` 의 `analyzeText` · `decide` 만** 사용한다. 화면 코드에서 점수를 따로 계산하지 않는다.
- `engine.js` · `engine.test.js` · `docs/기대값표.md` 는 고치지 않는다.
- 상태(`useState`)는 `App` 에 둔다: 내용 · 별점 · 결과. 입력이 바뀌면 이전 결과는 지운다.
- 입력칸과 별점에는 `label` 을 연결하고, 버튼에는 `type="button"` 을 쓴다.
- 폭 360px 휴대폰에서도 가로 스크롤이 생기지 않게 한다.
- 사용자가 입력한 글은 화면에 글자로만 보여 준다 (`dangerouslySetInnerHTML` 금지).

| 파일 | 하는 일 |

## 6. 11단계 — 이름 TrustTab · 일반 사이트 기능 (사용자 결정 2026-11-08)

서비스 이름을 **TrustTab** 으로 바꾼다 (Tab = 계산서: 믿을 수 있는 계산서에서만 리뷰). 컨트랙트 이름 `FairReview` 와 서명 태그 `FairReview.AIVerdict.v1` 은 **바꾸지 않는다** — 바꾸면 다시 배포해야 하고 이미 기록된 리뷰 · 서명과 맞지 않는다.

| 기능 | 내용 |
|---|---|
| 이름 · 로고 | 머리글 `TrustTab`, 홈 제목 `TrustTab 은`, 로고 `T` + 확인 표시 (`public/icon.svg`) |
| 탭 제목 | 화면마다 다름 (React 19 `<title>`): `가게 이름 · TrustTab` 등 |
| 공유 미리보기 | Open Graph · Twitter 카드, `og.png` 1200×630, 설명문, canonical |
| 앱 설치 | `manifest.webmanifest` · 아이콘 192 · 512 · maskable · apple-touch, theme-color |
| 검색 | `robots.txt` · `sitemap.xml` (빌드 때 주소에 맞게 생성), 관리자 · 사장님 화면은 `noindex` |
| 보안 정책 | 배포 화면에 CSP: 이 사이트 · 공개 노드 · 오라클(localhost:8787) 말고는 접속 금지, referrer 정책 |
| 접근성 | 본문으로 건너뛰기 링크, 화면이 바뀌면 맨 위로 + 본문에 초점 |
| 오류 · 끊김 | 화면 오류 시 안내 카드(오류 원문 숨김), 인터넷 끊김 안내 |
| 약관 | `/terms` 이용약관 · `/privacy` 개인정보처리방침 (실제로 하는 것만 적음) · 바닥글 링크 |
| 지갑 | 다시 방문 시 자동 연결 · 연결 끊기 기억 · Sepolia 자동 전환/추가 · 여러 지갑 중 MetaMask (docs/화면연결설계.md 8절) |
| 사장님 | `/owner` 결제 기록 → 결제 번호 + 리뷰 링크 (docs/화면연결설계.md 8절) |
| 관리자 운영 | `/admin/ops` 운영 상태 · 등록된 가게 · 가게 등록 · 긴급 정지/재개(한 번 더 확인) — Remix 대신 |
| 묶음 나누기 | react · ethers 를 따로 묶어 500kB 경고 해결, 재방문 때 캐시 |

화면 테스트: `web/src/test/site.test.jsx` S1~S21 (21개). 하나씩 기능을 지워 보는 방식으로 14개 기능을 테스트가 잡는지 확인했다. 상용화 기능 전체 설명은 [상용화](상용화.md).
