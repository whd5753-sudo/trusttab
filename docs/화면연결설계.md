## 3. 리뷰 제출 흐름 (`/stores/:id/review`)

1. AI 검사 (4단계 엔진) → **게시**일 때만 제출 칸이 열린다. 보류 = 10단계(오라클 · 사람 검토), 거부 = 제출 불가
2. 지갑 연결 · Sepolia 확인 (아니면 `Sepolia 로 전환` 버튼 = `wallet_switchEthereumChain`)
3. 결제 번호 입력 → **서명 전에 미리 확인** (수수료 낭비 방지, 최종 판단은 컨트랙트)
   - 없는 결제 · 다른 가게 결제 · 남의 결제 · 이미 쓴 결제 → 바로 안내
4. MetaMask 서명 → 블록에 담길 때까지 기다림 → 제출 완료 · Etherscan 링크 · 포인트 다시 읽기 (+10)

## 4. 오류 → 한국어 (`contracts/errors.js`)

| 오류 | 문장 |
|---|---|
| MetaMask 취소 | MetaMask 에서 요청을 취소했습니다 |
| 다른 가게 결제 (화면 검사) | 이 가게의 결제가 아닙니다. 결제 번호를 확인해 주세요 |
| `PaymentNotFound` | 없는 결제 번호입니다 |
| `NotPaymentCustomer` | 이 결제를 한 손님의 지갑이 아닙니다 |
| `AlreadyReviewed` | 이미 리뷰를 쓴 결제입니다 |
| `ReviewExpired` | 결제 후 30일이 지나 리뷰를 쓸 수 없습니다 |
| `InvalidRating` · `EmptyContent` · `ContentTooLong` · `ContractPaused` | 각각의 안내 |
| 수수료 부족 | 수수료로 낼 SepoliaETH 가 부족합니다 |
| 그 밖 | 블록체인 요청이 실패했습니다. 잠시 후 다시 시도해 주세요 (원래 메시지는 보여 주지 않음) |

## 8. 11단계 — 지갑 자동 연결 · 사장님 결제 기록

### 지갑 (state/WalletContext.jsx)

| 상황 | 동작 |
|---|---|
| 다시 방문 | `eth_accounts` (창 없음)로 이 사이트에 허락된 계정이 있으면 바로 연결. 허락이 없으면 빈 배열 → 그대로 |
| 연결 끊기 | 화면 상태 지움 + 이 브라우저에 `trusttab:wallet = disconnected` 기억 + `wallet_revokePermissions` (MetaMask 의 사이트 허락도 거둠) → 다음 방문에 자동 연결 안 함 |
| 지갑 연결 | `eth_requestAccounts` → Sepolia 가 아니면 바로 `wallet_switchEthereumChain`, 지갑에 없으면(4902) `wallet_addEthereumChain` (공개 노드 · Etherscan 주소 포함). 연결 직후 자동 전환을 취소하면 오류 문구 없이 머리글 경고로 안내 |
| 지갑 여러 개 | EIP-6963 으로 알린 지갑 중 MetaMask(`io.metamask`) 먼저, 없으면 `window.ethereum` |
| 지갑 없음 | PC: "MetaMask 설치하기" 링크, 휴대폰: "MetaMask 앱에서 열기"(metamask.app.link) |

Remix 는 별개 사이트라 그쪽 연결은 Remix 가 관리한다. 11단계부터 결제 기록은 Remix 대신 TrustTab `/owner` 에서 한다.

### 사장님 결제 기록 (pages/OwnerPayments.jsx · contracts/owner.js)

1. 사장님 지갑 연결 → `storeCount` · `stores(id).owner` 로 내 가게 찾기 (없으면 안내만)
2. 손님 지갑 주소 · 금액 입력 — 주소 형식, 사장님 본인 지갑(셀프 결제), 금액 1~10,000,000원을 **MetaMask 창 전에** 검사
3. `recordPayment(storeId, customer, amount)` MetaMask 서명 → 기록 대기 → 영수증의 `PaymentRecorded` 에서 결제 번호
4. 결제 번호 + 리뷰 링크(`/stores/1/review?payment=N`) + 링크 복사. 손님이 링크로 들어오면 결제 번호가 미리 채워짐
5. 최근 결제 20건 (`PaymentRecorded` 이벤트 + `payments(id).reviewed`)

ABI 추가: `storeCount` · `recordPayment` · `PaymentRecorded` · 오류 `StoreNotFound` `NotStoreOwner` `ZeroAddress` `InvalidAmount` `SelfPayment` (한국어 문장 포함, contracts.test 가 확인)

### 관리자 운영 (pages/AdminOps.jsx · contracts/admin.js)

1. `admin()` · `paused()` · `storeCount` · `stores(id)` 읽기 → 운영 상태 알약(정상 운영 중 / 긴급 정지 중) · 등록된 가게 목록 (화면 메뉴 데이터가 없는 가게는 '메뉴 정보 없음')
2. 관리자 지갑 + Sepolia 일 때만 버튼. 아니면 보기만
3. 가게 등록: 이름(앞뒤 공백 제거, 1~40자) · 사장님 주소 검사 → `registerStore` → 영수증 `StoreRegistered` 에서 새 번호
4. 긴급 정지 · 다시 켜기: 버튼 → **한 번 더 확인** → `pause()` / `unpause()`

ABI 추가: `paused` · `registerStore` · `pause` · `unpause` · `StoreRegistered` · 오류 `EmptyName`
